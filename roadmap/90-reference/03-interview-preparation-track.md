# Interview Preparation Track

Back to [Roadmap Index](../README.md)

## Why This Reference Matters

Interview performance is not only about knowledge. It is about how well you can explain, defend, and adapt what you know under time pressure.

This reference is the companion track for learners whose roadmap should also support hiring outcomes.

## Core Areas

You should be ready to discuss:

- Python fluency
- SQL
- backend architecture
- data modeling
- model API integration
- RAG design
- tool calling
- evals and reliability
- cost and monitoring tradeoffs

## What Interviewers Are Usually Testing

Across these topics, interviewers are often really testing:

- clarity of thought
- decomposition ability
- tradeoff judgment
- debugging mindset
- honesty about uncertainty

## Core Technical Story Types

Every serious project should be convertible into these interview story types:

- design story
- debugging story
- tradeoff story
- failure-and-fix story
- user-value story

## Questions To Answer Well

You should have strong answers for:

- when to use RAG vs fine-tuning
- how to evaluate an AI feature
- how to reduce hallucinations
- how to handle long-running AI tasks
- how to measure cost and quality
- when an agent is unnecessary complexity
- how you structured one of your production-style projects

## Preparation Structure

Prepare at three depths:

### Level 1: fast answers

- 30-second self intro
- short explanations of your strongest projects

### Level 2: detailed walkthroughs

- 3-minute project summary
- architecture and tradeoff explanation

### Level 3: design and challenge discussion

- 10-minute system design answer
- deep follow-up on failure modes, scaling, and iteration

## How To Practice

For each core project, prepare:

- what problem it solved
- why you chose the architecture
- what broke
- how you improved it
- what you would change next

## Good Interview Habits

- answer the question first, then expand
- speak concretely
- use one real project as evidence
- admit uncertainty honestly when needed

## Common Mistakes

- speaking only in buzzwords
- giving feature lists instead of architectural reasoning
- avoiding tradeoff discussion
- pretending certainty where you do not have it

## Expert Notes

### Interviews reward explanation, not only implementation

A project becomes much more valuable when you can narrate it well.

### Tradeoff language is a strong signal

Many technically strong candidates sound stronger simply because they explain decisions clearly.
