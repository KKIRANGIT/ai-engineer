# Branching and Pull Request Workflow Lab

## What This Exercise Trains

- branch isolation
- focused changes
- branch naming
- PR thinking even before GitHub is involved

## Practice Target

Use:

- [git-practice-sandbox](../../projects/git-practice-sandbox)

## Suggested Flow

1. Make sure your main branch is clean.
2. Create a new branch such as `feature/update-sample-data`.
3. Edit `data/tasks.txt`.
4. Commit only the task-data change.
5. Switch back to your main branch.
6. Compare the branches.
7. Merge the feature branch.

## GitHub Extension

If this sandbox is pushed to GitHub:

1. push the feature branch
2. open a pull request
3. review the changed files
4. merge after checks pass

## Success Check

You should be able to explain:

- why the branch existed
- what the branch isolated
- what the PR would show to a reviewer
