# Multi-User Test Scenarios

Run or reason through these cases:

1. A user from workspace A requests a ticket from workspace B.
2. A workspace member tries to reassign a ticket they do not own.
3. A workspace admin updates a ticket assigned to another teammate.
4. An unauthenticated request hits a protected route.
5. A valid user token references a deleted or missing user.

If you cannot describe the expected behavior for each case, the access model is still too fuzzy.
