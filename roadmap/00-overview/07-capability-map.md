# Capability Map

Back to [Roadmap Index](../README.md)

## Why A Capability Map Matters

Many learners evaluate themselves by topic exposure:

- "I learned RAG."
- "I learned agents."
- "I learned Next.js."

That is not a serious readiness model.

A stronger model is capability-based. It asks:

- what can you reliably do
- under what constraints
- with what level of independence
- and with what quality of reasoning

This roadmap is designed to build seven capability layers. Weakness in one layer can cap the value of the others.

## Layer 1: Software Foundation

This is the base layer.

It includes:

- Python
- TypeScript
- Git
- HTTP
- SQL
- CLI fluency
- testing basics
- debugging discipline

### What competence looks like

- you can structure code cleanly
- you can read and write APIs
- you can query and model relational data
- you can debug with method rather than random changes

### What weakness looks like

- tutorials are still doing too much of the thinking for you
- simple environment or Git issues slow you down disproportionately
- backend bugs feel mysterious rather than diagnosable

## Layer 2: Data and Systems

This is where software starts to feel like infrastructure rather than scripts.

It includes:

- PostgreSQL
- data modeling
- file storage
- queues and background work
- deployment
- logs and observability
- caching basics

### What competence looks like

- you can model app data intentionally
- you understand where data lives and how it moves
- you can design around long-running or async tasks
- you can reason about operational failure points

### What weakness looks like

- your apps work only locally
- you do not know how background or retry behavior should work
- you treat databases and infrastructure as magic boxes

## Layer 3: Model Integration

This is where AI capability enters the system.

It includes:

- provider APIs
- prompt design
- structured outputs
- model selection
- tool schemas
- basic multimodal inputs
- token, latency, and cost awareness

### What competence looks like

- you can choose a provider or model intentionally
- you can produce schema-safe outputs
- you understand how model behavior interacts with application logic

### What weakness looks like

- you rely on vague prompting
- parsing is brittle
- model choice is based on trend-following instead of task fit

## Layer 4: Retrieval and Grounding

This is the layer that turns many AI apps from generic assistants into trustworthy systems.

It includes:

- embeddings
- chunking
- metadata
- indexing
- filtering
- reranking
- citations
- retrieval evaluation

### What competence looks like

- you can explain why a retrieval system succeeded or failed
- you can tune chunking and metadata strategy intentionally
- you understand that retrieval quality is a full pipeline problem

### What weakness looks like

- you think "vector database" is the whole retrieval design
- you cannot diagnose grounding failures
- your answers sound plausible but are weakly supported

## Layer 5: Agent Workflows

This layer is about multi-step action and orchestration, not just chat.

It includes:

- tool loops
- planner-executor patterns
- workflow graphs
- approval boundaries
- durable execution
- memory and state decisions
- failure containment

### What competence looks like

- you know when an agent is justified
- you can orchestrate multi-step workflows safely
- you avoid overcomplicating systems that do not need agents

### What weakness looks like

- you build agents as a default instead of a deliberate choice
- you cannot explain the control loop
- failures become hard to inspect or reproduce

## Layer 6: Product Engineering

This is what turns technical capability into usable software.

It includes:

- frontend UX
- auth
- billing
- analytics
- error monitoring
- background jobs
- streaming UX
- rate limiting and usage controls

### What competence looks like

- users can sign up, use the app, and understand what is happening
- the system can enforce access and usage boundaries
- the product can be monitored and improved

### What weakness looks like

- the AI feature exists but the product shell is weak
- there is no operational visibility
- the app feels like a demo rather than a usable tool

## Layer 7: Career and Monetization

This layer is about converting skill into opportunity.

It includes:

- portfolio quality
- case studies
- proposals
- interview storytelling
- scoping
- pricing awareness
- distribution and visibility

### What competence looks like

- you can present your work clearly
- you can connect technical details to value
- you can answer "why does this matter" without hand-waving

### What weakness looks like

- you have built things but cannot frame them convincingly
- your portfolio is sparse or unclear
- you cannot translate capability into opportunity

## How These Layers Interact

These layers are not isolated.

Examples:

- weak Layer 1 slows everything above it
- weak Layer 4 makes many AI products untrustworthy
- weak Layer 6 makes strong AI features hard to use
- weak Layer 7 makes strong technical work hard to convert into jobs or clients

This is why the roadmap does not stop at model APIs or prompting. Real-world leverage comes from the combination.

## A Better Self-Assessment Method

Rate yourself on each layer using three questions:

1. Can I do this with little external guidance?
2. Can I explain the tradeoffs involved?
3. Can I show proof that I have done it?

If the answer to any of those is consistently "no", the layer is not strong yet.

## Final Rule

Do not claim readiness because one layer is strong.

Real readiness looks more like this:

- solid software foundations
- practical AI integration skill
- credible grounding and eval habits
- production-minded product engineering
- visible proof and clear communication

That is the capability profile this roadmap is designed to build.
