# Week 10 Study Plan

Back to [Week 10](../README.md)

## Objective

Use this week to become deliberate about prompt design and output contracts.

The main success condition is not:

"I got the model to answer nicely."

It is:

- I can define the task clearly
- I can shape the output intentionally
- I can validate the result
- I can compare prompt variants with real cases

## Suggested Order

### Day 1

- read the Week 10 README
- complete the prompt clarity exercise
- rewrite two prompts yourself

### Day 2

- complete the decomposition exercise
- decide which parts of the support-ticket task belong in prompt instructions versus schema design

### Day 3

- complete the prompt organization exercise
- compare the plain and XML-style prompt variants in the project

### Day 4

- inspect the JSON schema
- inspect the structured output request builder
- understand how the project treats refusals and validation

### Day 5

- inspect the regression cases
- run the regression harness in mock mode
- read the failures carefully

### Day 6

- inspect the prompt library and compare the prompt variants
- explain which variant is clearer and why

### Day 7

- read the structured output checklist
- write your own summary of what makes a prompt production-usable instead of demo-usable

## Minimum Success Definition

You should not leave this week saying:

"I know prompting better."

You should leave saying:

"I can design prompts as task specifications, define structured output contracts, and test prompt behavior against cases instead of relying on guesswork."
