## Why Grounded UX Matters

A grounded answer is only useful if the user can inspect the basis for the answer.

That means the system should surface:

- the answer
- the supporting chunks
- the document names
- a signal when the answer is weak or uncertain

## Better User Experience Patterns

- cite the document title
- show short source snippets
- surface chunk IDs for debug or audit usage
- admit when evidence is incomplete

## Weak UX Pattern

"Here is the answer. Trust me."

That is not enough for policy, support, legal, operational, or research workflows.

## Good Engineering Attitude

Grounding should change both the backend and the user experience. If the user cannot inspect support, the trust benefit of retrieval is reduced.
